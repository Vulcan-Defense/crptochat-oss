02verifique o que você baixa

Um chat cifrado só vale se o binário for o original.

Toda release é assinada com Ed25519: o manifesto RELEASE traz a versão e o SHA-256 de cada binário, e o RELEASE.sig é a assinatura dele. Esta é a chave de assinatura das releases:

fingerprint:
SHA256 aae1 82c8 5665 f874 fab6 a97e 93c5 333b aae8 ce15 7090 f247 c9e7 e2e6 f9d2 3890

chave pública:
UXnFSaezyEwMqfhfGncgjf03YiSN/FvaIja1Kv6g5VE=

Confira a mesma fingerprint por outro canal: no README do repositório do código ou com quem te passou o link. Se alguém trocasse esta página, trocaria a chave também.

  • O install.sh confere a assinatura do RELEASE com essa chave e o SHA-256 do binário contra o manifesto assinado; qualquer divergência cancela a instalação.
  • Os mesmos arquivos ficam espelhados nas releases públicas em github.com/hacking-table/crptochat-client/releases. Baixar dos dois lugares e comparar é uma conferência a mais: quem quisesse enganar você teria de alterar os dois.

Conferência rápida do hash, com o SHA256SUMS na mesma pasta do binário:

sha256sum -c --ignore-missing SHA256SUMS          # Linux; no macOS: shasum -a 256 -c --ignore-missing SHA256SUMS
# deve dizer: crptochat-linux-amd64: OK

O SHA256SUMS não é assinado: ele prova que o download não corrompeu, não quem publicou. Para isso, confira o SHA256SUMS do site com o do espelho no GitHub, ou faça a conferência completa abaixo, que usa o RELEASE assinado.

Conferência completa (assinatura + hash), no seu sistema:

Troque o nome do arquivo se for ARM64:

# 1) assinatura do manifesto (OpenSSL 3)
printf -- '-----BEGIN PUBLIC KEY-----\nMCowBQYDK2VwAyEAUXnFSaezyEwMqfhfGncgjf03YiSN/FvaIja1Kv6g5VE=\n-----END PUBLIC KEY-----\n' > crptochat.pub
openssl base64 -d -A -in RELEASE.sig -out RELEASE.sig.bin
openssl pkeyutl -verify -pubin -inkey crptochat.pub -rawin -in RELEASE -sigfile RELEASE.sig.bin
# deve dizer: Signature Verified Successfully

# 2) SHA-256 do binário contra o manifesto assinado
grep ' crptochat-linux-amd64$' RELEASE | sha256sum -c -
# deve dizer: crptochat-linux-amd64: OK

chmod +x crptochat-linux-amd64

O openssl do sistema (LibreSSL) não confere Ed25519. Use o do Homebrew (brew install openssl@3), trocando openssl por $(brew --prefix openssl@3)/bin/openssl nos comandos de Linux para a assinatura. Para o hash:

grep ' crptochat-macos-arm64$' RELEASE | shasum -a 256 -c -
chmod +x crptochat-macos-arm64
xattr -d com.apple.quarantine crptochat-macos-arm64   # o binário não é assinado pela Apple

No PowerShell:

$esperado = (Select-String -Path RELEASE -Pattern ' crptochat-windows-amd64\.exe$').Line.Split(' ')[0]
$atual = (Get-FileHash crptochat-windows-amd64.exe -Algorithm SHA256).Hash.ToLower()
if ($atual -eq $esperado) { "OK" } else { "NÃO CONFERE: não execute" }

A assinatura do RELEASE no Windows: rode os comandos de Linux no Git Bash, que já traz o OpenSSL 3.

Se qualquer conferência falhar, não execute o arquivo e avise no grupo.

03conecte

O --pin amarra o cliente a este servidor desde a primeira conexão.

./crptochat-linux-amd64 crptochat.acpt.app.br --pin __PIN__

No Windows: .\crptochat-windows-amd64.exe crptochat.acpt.app.br --pin __PIN__

fingerprint do certificado do servidor (o --pin):
__PIN__

Com o --pin, o cliente recusa qualquer servidor que não seja este, já na primeira conexão.

  1. Na primeira vez, escolha um nick e uma senha. A senha protege a sua chave neste computador e nunca vai ao servidor. O nick fica preso à sua chave: sem a chave, ninguém (nem você) recupera o nick.
  2. Sem cadastro: crptochat crptochat.acpt.app.br -a entra como anônimo, com um nick descartável (anônimos não recebem mensagens offline).
  3. Esc abre o menu com tudo. Para começar: /join #lobby.
  4. Com quem importa, confira o número de segurança: /whois nick e depois /verify nick.

↻atualizações

Dentro do chat, /update procura versão nova neste site e só instala uma release assinada com a chave acima e de versão maior que a sua (nunca volta para uma mais antiga, nem reinstala a mesma). Antes de trocar o binário, confere o SHA-256 dele contra o manifesto assinado. Não precisa de conta nem de login.

Tem a 1.9.0 ou anterior? Essas versões procuram atualização em outro lugar e não vão achar. Baixe a versão nova aqui uma vez (passos 1 e 2); daí em diante o /update funciona.

★novidades até a 1.16

Tudo negociado com quem está do outro lado: clientes antigos continuam conversando normalmente.

1.12

Double Ratchet nas diretas

Chave X25519 nova a cada troca de vez. Quem copiar o estado do seu cliente perde o acesso assim que vocês se respondem.

como funciona

A raiz absorve DH(chave nova, última do outro) a cada vez; dentro dela, uma chave por mensagem por HMAC. Mensagens fora de ordem abrem, repetidas são recusadas.

1.13

Recado para quem está offline

Mande a mensagem mesmo com a pessoa desconectada: ela fica guardada cifrada e chega quando ela voltar (até 14 dias).

como funciona

No estilo X3DH: prekeys assinadas e de uso único. O servidor guarda só destinatário, horário e bytes opacos; quem escreveu vai dentro do envelope, assinado.

1.14

Camada pós-quântica

ML-KEM-768 misturado ao X25519: gravar o tráfego hoje para quebrar com computador quântico amanhã não funciona.

como funciona

Como o PQXDH do Signal: HKDF(DH ‖ ss_ML-KEM) no ratchet e na caixa postal. Se o servidor tentar tirar a chave pós-quântica de quem já tinha, o cliente percebe e não envia.

1.15

Tamanho escondido

Um "ok" e uma frase curta saem com o mesmo tamanho cifrado. Teste no laboratório abaixo.

como funciona

Até 4 KiB, o conteúdo é completado até a próxima potência de 2 (64, 128, 256 … 4096 bytes); acima disso, de 64 em 64.

1.11

Convite com a chave do canal

/create #canal privado gerar sorteia uma senha de 128 bits; /invite nick leva a chave cifrada de ponta a ponta.

como funciona

Vão as chaves derivadas do canal, nunca a senha. Quem é convidado entra com /join #canal, sem digitar nada, inclusive se estava offline.

1.16

Responder, reagir, editar

/reply, /react 👍, /edit, /del e confirmação de leitura opcional.

como funciona

Tudo dentro das mensagens cifradas. A confirmação de leitura (/receipts on) vem desligada e só vale se os dois ligarem. Apagar é um pedido: quem já leu, leu.

{ }código aberto

O crptochat é software livre, sob a licença MIT. Todo o código (cliente, servidor e este instalador) está em github.com/hacking-table/crptochat-oss: dá para ler, auditar, compilar você mesmo e rodar o seu próprio servidor.

Quer melhorar algo? Faça um fork e mande um pull request. Antes, leia o CONTRIBUTING.md (como rodar os testes e o que é esperado de um PR).

!segurança

Achou uma vulnerabilidade? Reporte em privado, pelo Private Vulnerability Reporting do GitHub. Os detalhes (o que entra no escopo, prazos e como acompanhamos) estão no SECURITY.md.

Por favor, não abra issue pública com vulnerabilidade. Uma issue aberta expõe o problema a todo mundo antes de existir correção.

Limites honestos: o servidor ainda vê metadados (quem está online, em que canal, quando e a faixa de tamanho das mensagens) e, enquanto um recado offline espera, que alguém deixou algo para aquele nick. Print de tela e cliente adulterado não têm como ser impedidos. O código ainda não passou por auditoria independente, mas é aberto: revise e reporte o que encontrar.
